This supersedes the older guided-story and October UI walkthrough instructions. Existing root manuals/PDF and historical reports are preserved; their screenshots predate this revision.

From `C:/ABYUD/HACKATHONS/LOREAL`, run `npm start`. Open http://127.0.0.1:8107/start. Stop an older server in its own terminal before starting this version. Sign in as `qa` using the privately generated password under `qa` in `qualityos/var/local-credentials.json`; do not copy credentials into documents or Git.

1. Choose **Inspect a packaging change**. Create the experiment with the original bottles, C01 caps and v1 setup. The main panel shows the earlier tested condition and genuine preloaded synthetic proof. Evidence is ready; permission is not granted automatically.
2. Choose **Try a new-supplier cap batch**, review C02 in the dialog and submit. Original caps/supplier and current caps/supplier appear side by side, with the changed field highlighted. The earlier study remains intact but does not cover this configuration. The affected commitment is further simulated production on the selected run; the other run is checked independently.
3. Choose **Start tests for this configuration**, then **Enter three specimen readings**. Supply `0.98, 1.00, 1.02`, the eligible T-01 reference and the default assumed bound. An empty set remains planned; a required set must be independently sufficient. Specimens are controlled fictional qualification samples, separate from routine sample production after QA permission.
4. In **Demonstration controls**, advance `24` fictional hours, then **Refresh fictional record feed**. This explicitly changes demo time and a synthetic freshness flag; it does not perform physical testing or reconcile a real source. Choose **Record the independent leak result**, then explicitly select `PASS` for this route. There is no default result. The aggregate input declares the same fictional outcome for every listed specimen.
5. The panel says tests are complete but production awaits QA. **Review and resolve the production pause**, then separately **Authorize bounded simulated production** for `10` units and `30` minutes, with an appropriate review note. Finally **Record authorized sample units** with `5`. Reload: five saved records remain. These are simulated units, not measured defects or packaging saved.

The full route is available from the one main panel; the four tabs remain for inspection. Required review notes explain their purpose and allow an editable example. A note cannot make invalid evidence pass.

## Failure and required recovery, separately

Create another experiment, explicitly change C01 to C02, and follow the same tests but supply `FAIL`. Torque does not overrule the independent result. The main panel leads through problem description, possible explanation and proposed controlled comparison. Keep bottles/caps fixed, select the alternate v2 setup and define fresh verification. The setting 1.04 is a fictional comparison, not a discovered safe optimum.

QA approves the plan, the operator records execution, and the panel requires a new action-linked set. Supply fresh values `0.99, 1.01, 1.02`, advance another 24 demonstration hours, refresh the fictional feed and explicitly supply the new outcome. With `PASS`, production still remains blocked until **Review the new verification**. Then resolve the pause, issue bounded permission and record units. With missing, unreliable, failed or inconclusive proof, do not expect a successful ending.

The old C02/v1 failure remains recorded; the changed C02/v2 condition is evaluated on its own evidence. For a genuine same-condition failure/retest conflict, a separate QA study determination is needed, supported by a distinct independently sufficient verified-action study. A later pass alone is insufficient. **Correct a saved leak result** is QA-only and for recording errors, not the normal failed-test recovery path.

## Controls that challenge the thesis

- **Compare covered alternative C03**: the explicit synthetic joint approval covers this alternative. Test readiness may remain; new scoped permission is still separate. Different does not automatically mean defective or uncovered.
- Expired T-02 reference: in-range readings remain unusable. A new certificate does not retroactively repair them.
- One fresh specimen after a QA-required action: old sufficient proof cannot fill that required set's gaps or bypass assessment.
- **Decision history**: select an earlier failed decision, inspect the read-only banner, then return to current. Recent views are capped at 100 events/decisions and 120 links; Export experiment provides the complete workspace record.
- Advanced reference withdrawal/correction: persisted historical-unit containment is separate from healthy future-scope permission. Potentially affected, held, rejected and defective are not interchangeable terms.

## What may be said about manufacturing

This is a working synthetic decision-support prototype, not L'Oréal's internal system or a validated packaging protocol. Non-disturbing application-torque observation is an assumption; removal torque is different. Sample count, limits, dwell, leak assay/conditions and real change triggers need a packaging expert. There are no measured physical outcomes, savings, industrial integrations or adoption results. Existing QMS/MES/change controls already overlap substantially.
