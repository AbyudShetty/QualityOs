# QualityOS product walkthrough

Use `qa` with the privately generated local password. Every action below produces real persisted synthetic state; no factory observation is implied. Create a new workspace for each clean presentation. This is a walkthrough script, not a recorded or timed three-minute claim.

## W1 — Qualification becomes stale and recovers

1. Open Line. The initial B01/C01/configuration-v1 proof ACCEPTS, while the run is only Ready for QA. Authorize simulated run with a review reason, then Continue simulation for two units. Readiness, permission and recorded production are separate.
2. Change assignment to closure C02. Old proof does not apply. The run holds. Select AUR-016 to inspect the independent qualified control; this lot change did not hold it. Return to AUR-015.
3. Open scoped study. In Qualification, Record observations with the expired T-02 reference. The value may be 1.00 N·m, but it is unusable proof. Inspect the raw observation and reference.
4. New reference for T-02, then Record observations again under that new reference. The old observations remain invalid. The independent functional endpoint is still missing.
5. Advance replay by 24 hours, then Confirm source health. Advancing logical time does not fabricate a source heartbeat or physically perform a 24-hour test. Record result as FAIL with a reason. Torque does not override that independently declared failure.
6. Open Investigation. Record hypothesis with supporting/refuting evidence where appropriate. Propose action using configuration v2, Approve action, then Record execution. This records a bounded test of an explanation; it does not confirm real causation.
7. Open fresh verification. In Qualification, record three fresh synthetic observations with the valid T-02 reference. Advance replay by another 24 hours, explicitly confirm the source, and record the independent outcome as PASS.
8. In Investigation, Assess effectiveness. Support is limited to the simulation and requires a complete fresh study. In Qualification, Resolve hold using the current ACCEPT snapshot; then separately Authorize simulated run with a bounded unit/time budget.
9. Continue simulation for five units in Line. Seven actual unit records now exist across the earlier and recovered conditions. Inspect their exact scope and permission lineage in Investigation.

The API checks these conditions independently of which buttons are available. An operator can capture observations and execute approved actions, but cannot approve QA steps. ADMIN also cannot sign QA permission.

## W2 — Late correction changes current implications

From a run that already produced units, inspect Evidence and choose an earlier ACCEPT snapshot. The banner identifies the original sequence and read-only AS_KNOWN view. Return to current.

In Investigation, revoke the reference used by the fresh observations over its actual replay measurement interval, with a reason. Current evidence holds; the existing permission is revoked. The five units that actually depended on that fresh reference appear as potentially affected, while the two earlier units do not. The original ACCEPT receipt remains visible.

Alternatively, append a functional correction using Correct result. The earlier fact remains; the replacement participates in current reassessment. A conflicting independent PASS/FAIL set holds for disposition. QA disposition records a simulated handling decision and never proves a physical defect or automatically grants a new run permission.

Change traceability completeness to Partial to inspect conservative impact broadening. This deliberately includes more possible units because exact exclusion is no longer justified.

## W3 — Clean and explicit-envelope controls

Create another workspace. Add a harmless review note and continue within a valid permission: it does not revoke proof. Change C01 to C03, which is explicitly covered by the original approved envelope. The evidence can remain ACCEPT, but the changed exact material scope still needs a current QA permission. C02 has no such coverage. No implicit same-family wildcard is used.

The S1/S2/S3 selector labels a scenario family. All begin from the same qualified synthetic baseline; the user creates the subsequent history through actual commands. Selecting S2 does not silently inject a failure or bypass a workflow.

## Evaluation and evidence

Line → Independent evaluation → Run independent evaluation persists the frozen-case comparison. QualityOS and the competent evidence-aware reference can both match all declared outcomes. That parity is shown deliberately. This is software-case correctness, not an estimated factory safety rate, classifier accuracy or physical waste reduction.

Export receipt downloads the current domain cut, source history, immutable decisions, actual-time audit and provenance as JSON. Export does not include passwords or session tokens. Raw local browser-review screenshots are in ignored `var/browser-review`; reproducible reviewed summaries are in `docs/validation`.
